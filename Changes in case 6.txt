When running 6 distinct ensemble architectures across a 5-Fold Cross-Validation, the computational overhead multiplies dramatically. Here is the exact process of what was changed to force it to execute much faster:

### 1. Maximum Multi-Core Utilization (`n_jobs=-1`)
By default, many scikit-learn and boosting algorithms only use a single CPU core. We unlocked your system's full parallel processing power by assigning all available threads to the base and meta-learners.
*   **Random Forest, XGBoost, & LightGBM:** We explicitly injected `n_jobs=-1`. This forces the algorithms to build their internal decision trees in parallel across all your CPU cores.
*   **K-Nearest Neighbors (KNN):** Distance calculation is incredibly slow. Adding `n_jobs=-1` forces the distance matrix calculations to be split across cores.
*   **CatBoost:** We applied `thread_count=-1`, which is CatBoost's native equivalent of utilizing all threads.

### 2. The LinearSVC Substitution
This was the biggest bottleneck in earlier iterations. The standard Support Vector Machine (`SVC`) uses the RBF (Radial Basis Function) kernel. Its time complexity is roughly **$O(N^2)$ to $O(N^3)$**, meaning it practically freezes when you feed it a massive dataframe.
*   **The Fix:** We swapped it out for `LinearSVC`. As documented directly in the code (`# Replaced slow exact RBF-SVC with high-speed Linear projection`), `LinearSVC` is specifically optimized for massive datasets and scales almost linearly **$O(N)$**. It provides the same boundary-pushing logic but in a fraction of the time.

### 3. Estimator Capping
When stacking, the meta-learner is doing the heavy lifting of figuring out how to combine the probabilities. The base learners don't need to be infinitely deep.
*   We capped `n_estimators=50` (and `iterations=50` for CatBoost) across the board. This is enough trees to get a highly accurate probability distribution without wasting hours over-optimizing the base layers.
